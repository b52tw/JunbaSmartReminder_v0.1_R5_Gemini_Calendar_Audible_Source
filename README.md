# Junba 智慧提醒 v0.1.5 R5 — Google 日曆提醒／Gemini／有聲通知修正版（候選原始碼）

**此 ZIP 是 Android 專案原始碼，不是已編譯 APK。** 沿用 R4 的套件名稱 `tw.junba.reminder`，面向 vivo V2413 / Android 16。尚未在 Android SDK / vivo 真機完成 R5 編譯及實測。

## 這版改了什麼

1. Gemini 不再固定使用已過期的 `gemini-2.5-flash`，預設使用官方目前穩定的 `gemini-3.8-flash`；設定頁提供 **查詢這把 API Key 可用的模型**（GET `/v1beta/models`），可點選保存，查詢仍透過 `generateContent`。API Key 原本本機加密儲存機制保留，不會顯示明碼。401/403/404/429 錯誤會給出不同提示。查詢可用模型不保證免費額度／實際生成成功。
2. 原 R4 的『申請日曆／通知權限』按鈕在已授權時不顯示結果，這版改為顯示確認說明與通知設定入口。
3. 新建 **Junba 鬧鐘音效 R5** 高重要性通知頻道，預設嘗試指定系統鬧鐘提示音（Android `RingtoneManager.TYPE_ALARM`）與震動、鎖定畫面通知；須至系統設定確認聲音／警示／允許在鎖定畫面顯示。這仍屬 Android App **單次通知提示**，不是 vivo 原廠時鐘的持續響鈴或稍後提醒。由系統通知權限／勿擾／省電政策決定是否能發出聲音，絕不能保證響鈴。
4. 從手機已同步、已授權且已勾選的日曆讀取**實際事件提前分鐘數**，包括多組如 1、30、7200 分鐘。舊版只有固定選單 0/5/10/30/60 分鐘。若值為「依日曆預設」(-1)，此版不推測分鐘數，而會要求到 Google 日曆確認個別活動提醒。
5. 日曆頁增加**啟用日曆有聲提醒自動同步**勾選。使用者自願開啟後，App 啟動／返回前景／手動同步時，將未來 45 天內最多 250 個已明確設定提醒時間的事件提醒，排入本機 Android AlarmManager。資料僅保存在 Junba 手機內，不更改 Google 日曆，讀取 Google 日曆已同步到手機的活動。關閉勾選會取消 Junba 自行建立的日曆鏡像提醒。需要精確鬧鐘及通知權限，休眠、省電與勿擾狀況仍須真機驗證。
6. 原廠時鐘仍只可逐筆建立／核對，**不能直接匯入全部原廠鬧鐘、不能保證日曆全部提醒都進 vivo 時鐘**。Android `ACTION_SET_ALARM` 不接受完整年月日，為防止錯誤地提前響起，對距離現在超過 24 小時的一次性提醒，這版不再直接送往原廠，改提示使用 Junba 本機日期準確的提醒。原廠建立請求 ≠ 已核對成功。
7. 繼承 R4 的記事、今日／本月月曆、原廠時鐘建立請求與核對歷史、JSON 備份、BootReceiver 重排程。

## 重新編譯

解壓縮後將 `app/`, `build.gradle`, `settings.gradle`, `gradle.properties`, `.github/workflows/build-apk.yml` 等專案檔案上傳至 GitHub repository 根目錄（不要再多一層資料夾）。GitHub Actions `Build Android APK` 成功後，從 Artifacts 下載 `JunbaSmartReminder-v0.1-R5-debug-APK`。

**非常重要：GitHub Actions 產出的 debug APK 若每次使用不同簽章，就會再次發生 INSTALL_FAILED_UPDATE_INCOMPATIBLE。** 若此前版本未建立共用正式簽署金鑰，請先透過 App 匯出 JSON 備份再換版。正式長期更新務必在 GitHub Secrets 使用持久的私有簽署金鑰；不要將 keystore 或密碼直接提交公共 Repo。

## 建議驗收順序

1. 安裝並打開 R5，確認「設定」→「申請日曆／通知權限」正常顯示已授權狀態；到通知類別選「Junba 鬧鐘音效 R5」設為有聲警示、鎖定畫面顯示。確認精確鬧鐘權限。
2. 在「設定」展開 Gemini，測試 `gemini-3.8-flash`；若失敗，使用「查詢可用模型」從該 Key 的實際返回清單選擇後再測。
3. Google 日曆建立測試活動，設定「5 天前、30 分鐘前、1 分鐘前」等多組明確提醒，等待手機日曆同步。Junba → 日曆 → 開啟日曆有聲提醒自動同步 → 立即重新同步，核對資訊。注意：5 天前可能已超過目前時間，過期提醒不會重新排程。
4. 建立 2～3 分鐘後的記事提醒，鎖定手機並實際聽是否發出聲音（此為 App 有聲通知，不是原廠時鐘）。
5. 用「建立／測試 vivo 原廠鬧鐘（2 分鐘後）」操作，必須到 vivo 時鐘核對後實測原廠聲音。兩類測試結果分開紀錄。

## 限制與未完成項目

- 未實作 Junba 自有「全螢幕持續鬧鈴／貪睡」Activity；這版只改善通知音效並增加日期準確的 AlarmManager 排程。
- 未實作長期背景定時 Google 日曆同步（僅在重新開啟／回前景／手動同步更新）與Google 雲端日曆 API 同步；僅讀取系統已同步的 CalendarProvider。
- 手機廠商可能限制精確鬧鐘、鎖屏通知、後台或通知音效，必須以真機驗證為準。
- 原生時鐘的全部鬧鐘、稍後提醒次數／剩餘次數不可透過 Android 公開 API 完整讀取；使用者需到 vivo 時鐘人工核對。
- **Java 原始碼已做語法層級解析檢查；仍須 GitHub Actions 真正編譯與 vivo 真機測試**。
